In short

caixa-do-agente (Agent Box) is a free kit for people who already use AI agents on their computer, such as Claude Code, Codex or DeepSeek Harness. The harness is the software around the model: it runs the commands, controls the permissions and keeps the history. The kit scores the harness you use from 0 to 10 and runs any agent or command in a disposable Docker box, with no internet and without your secrets files (.env). You need Docker and Python 3.

What it is

Three pieces, one idea: take care of the agent's body

DeepSeek reported that the same model (V4.1 Flash) solves 65.6% of the DeepSWE tasks (a benchmark of real coding tasks) inside Codex and 74.2% in a minimal harness (mini-SWE): almost 9 points just by swapping the harness (model card). This kit brings that idea to your machine.

📊 auditar.py

Reads the settings of Claude Code, Codex and DeepSeek Harness and gives a 0 to 10 score across 6 layers: box, approval, guardrails, verification, context and secrets. It only reads, it changes nothing.

📦 caixa.sh

Copies the project without the secrets, runs the command in a container with no network and with memory, CPU and time limits, shows what changed and deletes everything. The original only changes with --aplicar.

🗺️ Kit map

Each missing layer points to an INEMA kit that fixes it: guardrails against prompt injection, lessons that become guardrails, project memory, local DeepSeek Harness.

How it works

The box cycle: create, execute, destroy

It is the same cycle DeepSeek uses to train its agents (more than 380 thousand boxes at the same time, according to its paper), at the scale of one person.

Copy without .env and keys→ Container with no network→ Memory, CPU and time limits→ Patch with the changes→ Container and copy deleted

User guide · step by step

From zero to your first box in 5 minutes

The commands use only what is in the repository. Steps 1 to 4, 6 and 7 and the first command of step 5 were run on this machine on 11/10/2026; the Claude Code examples depend on your key or login.

Flags and script output are in Portuguese: --aplicar = apply, --rede = network, --montar = mount, --interativo = interactive, --memoria = memory, --tempo = time, --imagem = image.

1

Get the kit

Clone the repository and enter the folder.

git clone https://github.com/inematds/caixa-do-agente && cd caixa-do-agente
2

Prove the box works

17 checks (the first time it downloads the node:22-slim image, ~250 MB; the --interativo check uses the script command): .env and keys stay out, network closed, original untouched, container deleted, --aplicar works, --env passes only the requested variable, --interativo opens a terminal, cache and node_modules do not return to the original, --help works, and the auditor detects a secret, a disabled sandbox and a machine with no harness.

bash testes/teste.sh  # ends with: TUDO OK (17/17)
3

Score your harness

Point it at one of your projects. The auditor reads the settings of Claude Code, Codex and DeepSeek Harness (DeepSeek's open-source agent, command dsh): ~/.claude/settings.json, ~/.codex/config.toml and ~/.dsh/settings.yaml (if they exist), and the project itself. Box, Approval and Guardrails come from the global settings combined with the project's, so projects on the same machine share those three.

Each layer is worth 2 points (OK), 1 (MEIO) or 0 (FALTA); the score is the sum divided by 12, times 10. Box: sandbox enabled in some harness. Approval: no harness in "skip everything" mode. Guardrails: deny rules (what the agent may never do) and PreToolUse hooks (a script that blocks the action beforehand). Verification: tests in the project and Stop/PostToolUse hooks (a script that checks afterwards). Context: AGENTS.md or CLAUDE.md. Secrets: no .env or key inside the project.

python3 auditar.py ~/meu-projeto        # 0 to 10 score + the next step for each layer
python3 auditar.py ~/meu-projeto --json # same thing, for use in scripts
python3 auditar.py --help               # the criterion for each layer
4

Run something in the box

Everything after -- runs inside the container, on a copy of the project. Left out of the copy: .env, keys and credentials, node_modules and .venv. No network by default; if the command needs to install dependencies, use --rede.

./caixa.sh ~/meu-projeto --imagem python:3.12-slim -- python3 -m unittest  # no dependencies, no network
./caixa.sh ~/meu-projeto --rede -- sh -c 'npm install && npm test'           # Node: installs and tests inside the box
5

Run an agent in the box

Agents need to talk to the model, so use --rede. There are two ways in:

With an API key: --env NOME passes only that variable from your terminal into the box. In headless mode (-p), Claude Code needs permission to run commands and edit files; inside the disposable box you can allow everything, because the worst case stays trapped in it.

With your subscription (login): open the agent with --interativo and log in inside the box. The login disappears when the box is destroyed.

To give access to one of your folders, use --montar origem:destino:ro (:ro = read-only). The project's secrets files still stay out.

./caixa.sh ~/meu-projeto --rede -- npx -y @deepseek-ai/dsh@latest --help  # tested: 1st time ~5 min (downloads the package)
./caixa.sh ~/meu-projeto --rede --env ANTHROPIC_API_KEY -- npx -y @anthropic-ai/claude-code -p "rode os testes e corrija o que falhar" --dangerously-skip-permissions
./caixa.sh ~/meu-projeto --rede --interativo -- npx -y @anthropic-ai/claude-code  # run /login inside
6

Review and apply

Each run that changes files saves a caixa-AAAAMMDD-HHMMSS.patch: a text file with the difference (the diff) of everything that changed. It is saved in the folder you ran the command from (or the one you set with --patch PASTA) and is there for you to review; you do not need to apply it with git apply. To copy the changes back, use --aplicar (asks for confirmation). New and changed files come back; node_modules, .venv and caches do not; a file deleted in the box is not deleted in the original.

less caixa-*.patch
./caixa.sh ~/meu-projeto --rede --aplicar -- sh -c 'npm install && npm run format'
7

Adjust the limits and the image

Default: image node:22-slim, 4 GB of memory, 2 CPUs, 30 minutes. Use --imagem when the command needs another language or tool (the Node image has no make, for example).

./caixa.sh ~/meu-projeto --rede --memoria 8g --cpus 4 --tempo 7200 -- sh -c 'npm install && npm run build'
./caixa.sh ~/meu-projeto --imagem python:3.12 -- make build  # full image, with make

Limits

What the box does not do

It is not a virtual machine

Docker isolates files, network and resources, but shares the system kernel. For code you don't trust at all, use a VM.

With network, data can leave

With --rede, the agent can send out whatever is in the copy. The secrets were already left out, the rest was not.

The auditor points, it doesn't guarantee

It reads the most common settings. A high score does not replace reviewing what the agent is allowed to do.
